## Решения по продукту и архитектуре

| № | Решение | Обоснование |
|---|---------|-------------|
| 1 | Один **модульный монолит**, не микросервисы | Проще развивать и деплоить; сервис выделяют при независимом релизе, команде, доступе или CI/CD |
| 2 | **Два уровня «проекта»**: бизнес-модуль = папка `modules/<name>`; пользовательский проект = запись в `platform.projects` | Пользовательский проект изолируется через `workspace_id`, отдельная БД/репозиторий на него не создаётся |
| 3 | `core` — только инфраструктура (config, db, logging, errors, security) | Не разрастается до «универсальной свалки» |
| 4 | Схема PostgreSQL — на бизнес-модуль (`platform` + отдельные схемы) | В одной БД, но разграничение владения таблицами |
| 5 | Миграции только добавляются, не переписываются | Alembic: новое изменение = новая ревизия |
| 6 | RBAC `user` / `admin`; авторизация отключена только в тестовом режиме | Определено ранее в диалоге |
| 7 | Секреты — файл окружения с правами `600`, в репозитории только `.env.example` | Проверка тока не по чату |

оказался пустым — содержимое пропало из видимости WSL (сбой метаданных 9p/DrvFs).

**Правила на будущее:**
1. На `/mnt/d` (DrvFs) каталоги **не перемещать через `mv`** — только `mkdir`/`clone`
   или `cp` + проверка контрольных сумм + удаление источника.
2. Если WSL показывает `d?????????` — проблему решать со стороны Windows
   (`Remove-Item -LiteralPath 'D:\…' -Recurse -Force`), не командами WSL.
3. Git-репозиторий создавать **сразу** — история и снапшоты страховали бы ситуацию.

## Новое ТЗ: платформа «Умный дом» (замена workspace→проект)

Владельцем доведено ТЗ словами. Зафиксировано в `overview.md` (разделы 1–3, 9–10).

| № | Решение | Примечание |
|---|---------|-----------|
| 1 | Иерархия **Дом → Модуль → Подмодуль** | дом = корень изоляции; «семья/workspace» упразднён |
| 2 | **Права `view`/`edit`** на каждый узел дерева | `edit ⇒ view` |
| 3 | **Роль = шаблон прав** (`can_view`, `can_edit`), **назначение = (user, роль, узел)** | наследование вниз по дереву; эффективные права = max |
| 4 | Роли seed: `superadmin` (platform), `owner` (home, edit), `user` (resource, view) | кастомные роли — из админки |
| 5 | Права — **только из БД**, никаких хардкодов «кто владелец» | владелец назначается через admin-API/SQL |
| 6 | **Суперадмин `ermoshinss`** — email для входа = `ermoshinss`, пароль из ENV | bootstrap `granted_by = NULL` — единственный бэкдор |
| 7 | Дерево ресурсов — `tenancy.resources` (node_type home/module/submodule) | модуль уникален в доме по module_code |
| 8 | Каталог: `climate`, `security`, `energy`; **вертикаль — `climate`** | `mail` из каталога исключён |
| 9 | Управление устройствами — ролям с `edit`; жилец — `view` (статус/показания) | —
| 10 | Таблицы вехи 1 (`workspaces/projects/workspace_members`, `module_grants`) — неиспользуемые | будут удалены миграцией после перевода на ресурсы |

Встроенные уроки прошлых ошибок: спека (включая экраны) фиксируется до кода;
права — один источник (`authz`), без дублей в tenancy; пароли и сессии сразу;
«мои» ресурсы фильтруются, чужое → 403; типы фронта из OpenAPI; git с первого
коммита; DrvFs без `mv`; секреты только в файле `600`.
